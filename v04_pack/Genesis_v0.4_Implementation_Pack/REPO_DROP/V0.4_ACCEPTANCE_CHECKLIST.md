# Genesis v0.4 Acceptance Checklist

Use this after Luna completes the v0.3→v0.4 reconciliation and before substantive betting research resumes.

## Foundation

- [ ] Current repo is the fresh Genesis repo, not a legacy sports-engine repo.
- [ ] Legacy repos remain read-only/unchanged.
- [ ] PROJECT_STATE.md identifies v0.4 as authoritative.
- [ ] V03_TO_V04_GAP_ANALYSIS.md exists.

## Evidence / PIT

- [ ] Source artifacts are immutable/content-addressed.
- [ ] Evidence manifests are append-only/tamper-evident.
- [ ] ready_at/published_at/retrieved_at semantics are implemented.
- [ ] Decision features go through a PIT/as-of interface.
- [ ] Frozen evidence packs have stable hashes.
- [ ] Historical decisions remain reconstructible after source corrections.

## Candidate / selection

- [ ] Candidate decision hash is deterministic.
- [ ] No opaque live confidence score controls qualification.
- [ ] PASS is fail-closed.
- [ ] Reason-code taxonomy is enforced.
- [ ] Normal odds range is 1.50–3.00.
- [ ] Exceptional 1.40–1.49 policy is separate.
- [ ] Price-sanity policy is explicit/versioned.
- [ ] Daily target ranges are search aims, not quotas.
- [ ] Selection does not stop early just because lower target is reached.

## Statistics

- [ ] All screened candidates are retained.
- [ ] Candidate-universe size/selection rank are recorded.
- [ ] Selected-set calibration is supported by evaluator interfaces.
- [ ] Dependence-aware evaluation is possible.
- [ ] PASS ablation/protected counterfactual evaluation is planned.
- [ ] Protected attempt accounting is non-refundable.

## LLM research

- [ ] Structured ResearchEvidence schema enforced.
- [ ] No direct LLM probability accepted.
- [ ] Extractor model/prompt/schema versions are recorded.
- [ ] Critical contradictions are explicit.
- [ ] Critical evidence has freshness/expiry rules.
- [ ] Execution-time critical evidence refresh is designed.

## Risk

- [ ] 1u = 2.5% bankroll represented as policy/config, not hard-coded ad hoc.
- [ ] 1–3u stake tiers supported.
- [ ] 60% hard open-liability policy represented.
- [ ] No daily turnover cap.
- [ ] Correlation/dependence group structure exists.
- [ ] Unmatched/pending/UNKNOWN exposure is counted correctly.
- [ ] Risk approvals are single-use.

## Execution / ledger

- [ ] No live credentials present.
- [ ] Research code cannot call live broker submission.
- [ ] Order state machine includes UNKNOWN / RECONCILIATION_REQUIRED.
- [ ] Duplicate-order prevention/idempotency is tested.
- [ ] Paper adapter follows same lifecycle as future live adapter.
- [ ] P/L comes only from settlement ledger.
- [ ] Partial fill/void/dead heat/non-runner/correction tests exist as applicable.

## Runtime / cost

- [ ] Runtime architecture does not require user's laptop to remain on.
- [ ] Cloud plan is provider-neutral and can target <=£10/month.
- [ ] OddsPapi quota ledger/batching plan supports <=7 calls/day, <=220/month.
- [ ] Architecture does not depend on a £499 Betfair live key.
- [ ] Venue interface is pluggable.

## Live boundary

- [ ] Live mode remains disabled.
- [ ] Research agent cannot change mode.
- [ ] Human authorization artifact is required for future MICRO_LIVE/LIVE.
- [ ] Kill switch blocks new orders but does not generic-cash-out outcome bets.
